# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A SwiftUI voice journal that transcribes spoken entries on-device with Apple's own
`SFSpeechRecognizer`, keeps the recording, and plays it back with the spoken sentence
highlighted. The interface implements `Yap Prototype.dc.html` from the Claude Design
project "Yap codebase audit request" (18 screens: onboarding, journal, calendar, recording,
writing, reading, insights, settings, Live Activity). The prototype's mocked behavior is
real here; see "Deviations from Yap Prototype.dc.html" below.

Transcription previously ran through a bundled Whisper CoreML model (via WhisperKit) as a
second pass after Stop. That's gone: the bundled model was a genuine liability (594MB→144MB
across two revisions, and the larger one crashed a real iPhone 12 into a full reboot from
memory pressure), and Apple's own on-device recognizer is already quite good, ships with the
OS, and needs zero load time.

## Build and test

`Yap.xcodeproj`, `Yap/Info.plist` and `YapWidgets/Info.plist` are **generated by XcodeGen and
gitignored** — never hand-edit them. Change `project.yml` instead, and re-run
`xcodegen generate` after adding, moving or deleting any source file.

```sh
cd ~/Documents/Yap
cp Yap/AI/Secrets.swift.example Yap/AI/Secrets.swift   # once; gitignored
xcodegen generate
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer

xcodebuild -project Yap.xcodeproj -scheme Yap \
  -destination 'generic/platform=iOS Simulator' build

# Install + launch on a booted simulator
SIM=<simulator-udid>
xcodebuild -project Yap.xcodeproj -scheme Yap -destination "id=$SIM" build
xcrun simctl install $SIM <DerivedData>/Build/Products/Debug-iphonesimulator/Yap.app
xcrun simctl launch $SIM com.timothykoelsch.Yap
```

Targets: `Yap` (the app, sources `Yap/` + `Shared/`) and `YapWidgets` (widget extension for
the recording Live Activity, sources `YapWidgets/` + `Shared/`). For device installation,
open the generated project in Xcode and select your own team for both targets. Never commit
a personal development-team identifier.

DEBUG-only launch arguments (read in `Store.applyLaunchOverrides` and
`OnboardingFlow.launchStep`) for screenshots of states with no cold-launch path:

```sh
xcrun simctl launch $SIM com.timothykoelsch.Yap -seedDemo -skipOnboarding   # sample journal, skip onboarding
xcrun simctl launch $SIM com.timothykoelsch.Yap -resetOnboarding -onboardingStep reminder
#   steps: welcome talk privacy name microphone reminder faceID allSet
xcrun simctl launch $SIM com.timothykoelsch.Yap -seedDemo -skipOnboarding -tab insights        # journal | insights | settings
xcrun simctl launch $SIM com.timothykoelsch.Yap -seedDemo -skipOnboarding -openCalendar
xcrun simctl launch $SIM com.timothykoelsch.Yap -seedDemo -skipOnboarding -openReading         # newest entry
xcrun simctl launch $SIM com.timothykoelsch.Yap -seedDemo -skipOnboarding -openWriting         # edit newest entry
xcrun simctl launch $SIM com.timothykoelsch.Yap -skipOnboarding -openRecording                 # "Listening…", no mic
xcrun simctl launch $SIM com.timothykoelsch.Yap -skipOnboarding -openRecording -recordingTranscript "Some words."
xcrun simctl launch $SIM com.timothykoelsch.Yap -skipOnboarding -simulateRecording "Some words."  # new draft from a transcript
xcrun simctl launch $SIM com.timothykoelsch.Yap -appearance Dark                               # Automatic | Light | Dark
xcrun simctl io $SIM screenshot out.png
```

`-skipOnboarding` and `-appearance` persist in UserDefaults like the real settings.

Live mic + transcription can't be scripted headlessly in the simulator (no fake audio
input); test that on a real device, or manually with the simulator's host-mic passthrough.
Also verify on a device: recording with the phone locked (background audio + Live
Activity), the Live Activity's Stop button, Face ID lock, and the daily reminder.

## Architecture

**`Store`** (`Yap/Store.swift`) is the single `@MainActor ObservableObject`: entries, the
navigation path, the selected tab/day, the active `RecordingSession`, the writing `Draft`,
toasts and alerts (as `AppAlert` data shown by `RootView`). It owns every mutation and is
injected with `.environmentObject`, mirroring the prototype's single `DCLogic` class.
**`Preferences`** (`State/Preferences.swift`) holds everything chosen in onboarding and
Settings in UserDefaults. **`AppLock`** handles Face ID / passcode, **`Reminders`** the daily
notification, **`Exporter`** Markdown/PDF/plain-text export and the share sheet,
**`InsightsSummary`** / **`HeatGrid`** (`State/InsightsData.swift`) the computed numbers.

Flow: a recording (`Store.startRecording`) opens `RecordingView` over everything with a
circular reveal from the button that started it. Stop (`finishRecording`) turns the
transcript into a `Draft` (sentences, two per paragraph; title from the first four words)
and pushes `WritingView` underneath as the recorder settles away. "Add voice" on the writing
screen records in `.append` mode and adds paragraphs + audio to the same draft. Nothing is
written to the journal until Save (`commitDraft`); Back on a new draft asks Save/Discard;
edits to an existing entry are kept on Back.

**Navigation**: `RootView` → `NavigationStack(path: $store.path)` whose root is `TabsRoot`
(Journal with its calendar, Insights, Settings, under the floating `TabBar`). `Route.reading`
uses the native zoom transition from the journal card; `Route.writing` turns off the edge
swipe through `NavigationGate` (a new draft must be saved or discarded). The navigation bar
is hidden everywhere; the `UINavigationController` extension in `RootView.swift` keeps the
edge-swipe back gesture working without it.

**`Transcriber`** (`Yap/Speech/Transcriber.swift`) runs one engine for both jobs: Apple's
on-device `SFSpeechRecognizer` (`requiresOnDeviceRecognition`, `addsPunctuation`, locale
`en-US`) drives the live captions *and* the saved transcript.

- Live captions are the recognizer's partial results. The newest two words show in the
  prototype's grey until the recognizer has been quiet for 0.8s (`LiveTranscript`).
- `pause()` closes out the current recognition request (so a long pause can't hit the
  recognizer's own time limit) and `resume()` starts a new one layered on
  `confirmedTextPrefix`. `taskGeneration` drops late callbacks from replaced tasks so they
  can't duplicate text.
- `AVAudioEngine` + one input tap feeds the recognizer and, resampled to 16kHz mono, a
  lock-guarded `AudioSampleAccumulator` — what `EntryAudioStore` saves as the entry's `.m4a`
  and waveform. The tap runs on a real-time audio thread, so it doesn't hop to the main actor.
- Level bars are driven by peak amplitude on those buffers, polled onto `levels` at 10Hz.
- **Views must observe `Transcriber` directly** (`@ObservedObject`), not read it off
  `store.transcriber` through `@EnvironmentObject var store` — `Store` does not forward
  `Transcriber`'s `objectWillChange`, so such a view only redraws when some unrelated `Store`
  property changes. `RecordingView` takes `transcriber` as an explicit parameter for this.

**Live Activity**: `Shared/RecordingActivity.swift` (compiled into both targets) defines
`RecordingActivityAttributes` and `StopRecordingIntent`, a `LiveActivityIntent` that runs in
the app's process and calls `RecordingIntentBridge.handler` (set by `Store`) — the same as
tapping Stop. `LiveActivityController` starts/updates/ends it; `YapWidgets` draws it. The
timer is `Text(timerInterval:pauseTime:)`, so it ticks without updates. `UIBackgroundModes:
audio` keeps capture running with the phone locked.

**`JournalSimplifier`** (`Yap/AI/JournalSimplifier.swift`) is the one network call: Format ›
Clean Up on the writing screen, only after the user allows it (Settings › Voice &
Transcription, or the prompt that explains it). The key lives in the gitignored
`Yap/AI/Secrets.swift`; a client-embedded key is extractable, so a distributed app needs a
server-side proxy.

**Persistence**: a flat `entries.json` in Documents (`Model.swift`, `EntryStore`), recordings
in `Documents/AudioEntries/<id>.m4a`, photos in `Documents/Photos/<uuid>.jpg` (`PhotoStore`).
Entry text keeps paragraphs separated by blank lines with `**bold**` / `*italic*` spans
(`InlineMarkdown`); `title`, `duration` and `photo` are optional so older files decode.
A real first launch starts with zero entries; `EntryStore.seedEntries()` (the prototype's
sample journal, dated relative to today) is reachable only via DEBUG `-seedDemo`.

## Design system

- `Design/Palette.swift` — the prototype's tokens as dynamic colors (light from the
  prototype, dark is this app's own), plus `yapCard` / `yapFrost` surface recipes.
- `Design/Typography.swift` — Newsreader is bundled as two variable fonts and built per size
  with explicit `wght` and `opsz` axes (`Font.news(size, weight, italic:)`); system text is
  `Font.sf(size, weight)`. Newsreader's ascent + descent is exactly 1em, so CSS line heights
  map to `newsLines(size, lineHeight:)`.
- `Shared/SVGPath.swift` + `Design/Icons.swift` — every icon is the prototype's own SVG path
  (`Glyph`, drawn by `GlyphView` with the prototype's stroke widths).
- `Design/Motion.swift` — easing curves, `staggerIn` (the prototype's `[data-st]` entrance),
  `PressStyle`, and `ScreenMetrics`: screens are laid out against the prototype's 402×874
  canvas with vertical offsets scaled to the screen height; `isCompact` (iPhone SE height)
  tightens the densest onboarding pages.
- Writing and reading text are `UITextView`s (`RichTextEditor`, `ReaderText`) for
  selection-based bold/italic and per-sentence highlight + tap.

## Deviations from Yap Prototype.dc.html

The prototype's `Component` class is a browser mock. Mocked behavior is real here, and a few
things changed on purpose:

- **Transcription, audio, playback**: real recognizer, real recording, real `AVAudioPlayer`
  (rate, ±15s, scrub). Sentence timing for "follow along" is estimated from character counts,
  as in the prototype.
- **No iCloud sync**: the prototype says entries sync through the user's iCloud. Nothing
  syncs (no CloudKit/iCloud entitlement), so that copy now says entries stay on this iPhone
  (screen 03, Settings profile row, About, the delete alerts), and the "Synced with your
  iCloud" pill became "Optional Face ID lock". Adding sync needs a team with the iCloud
  capability; change the copy back if it's built.
- **"Sign In"** on the welcome screen skips onboarding, as in the prototype; there are no
  accounts to sign in to.
- **Photos** are real photos from the photo picker (the prototype offers three gradients).
- **Clean Up** calls the NVIDIA API instead of a regex, gated as described above.
- **Insights**: themes, quotes, the longest entry and "you usually journal around" are
  computed from entries (the prototype hardcodes Gratitude/Focus/Rest and "8 PM").
- **Name** has no default ("Jordan" in the prototype) and can be edited from Settings.
- **Reminder** sheet adds "Turn Off Reminders", since the copy promises it can be turned off.
- **Support email** is the prototype's `support@yap.app` (`SettingsView.supportEmail`) —
  replace it with a mailbox you own before shipping.
- **Native components** where the prototype imitates iOS: alerts, menus, the time sheet, the
  share sheet, the system permission prompts (prototype screen 06) and the Lock Screen
  (screen 18 is the Live Activity, not a fake lock screen).
- **Toast**: grows out of the Dynamic Island on phones that have one; fades in under the
  status bar on phones that don't.
- Accent is the prototype's default `#2F6BF2` (its `accent` prop also offered `#3F6687`, this
  app's earlier blue); still one blue accent, no picker.
